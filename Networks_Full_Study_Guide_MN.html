Сүлжээний бүрдэл хэсгүүд

Сүлжээн дэх ямар ч компьютер нь хост буюу төгсгөлийн төхөөрөмж юм. Хостуудыг дараах байдлаар ангилна:

  • Сервер — нөөц хангадаг (веб сервер, имэйл сервер, файл сервер).
  • Клиент — серверт хүсэлт илгээдэг (хөтөч, имэйл клиент).
  • P2P (Үе тэнгийн-үе тэнгийн) — нэг төхөөрөмж хоёр үүрэг хавсарч гүйцэтгэнэ. Маш жижиг сүлжээнд л хэрэглэнэ. Сул тал: төвлөрсөн удирдлага байхгүй, аюулгүй бус, өргөтгөх боломжгүй.

Завсрын төхөөрөмжүүд (Intermediary devices): свитч, роутер, WAP, firewall. Тэдгээрийн үүрэг: дохиог сэргээх, чиглүүлэлтийн мэдээлэл хадгалах, алдааны талаар мэдэгдэх.

Найдвартай сүлжээ — 4 шинж чанар

✅ Дөрвөн тулгуур
  • Fault Tolerance — алдааг тэсвэрлэх чадвар: нэг зам унахад өгөгдөл нөгөөгөөр (packet switching) явна.
  • Scalability — өргөтгөх чадвар: гүйцэтгэл буурахгүйгээр шинэ хэрэглэгч нэмэх боломжтой.
  • QoS (Үйлчилгээний чанар) — дуу, видео тасалдалгүйн тулд тэргүүлэх ач холбогдол шаардана.
  • Security — гурван зорилго: Нууцлал (Confidentiality), Бүрэн бүтэн байдал (Integrity), Хүртээмж (Availability) — CIA Triad.

Чиг хандлага ба технологи

  • BYOD — Өөрийн төхөөрөмжийг авчрах: ажилтнууд өөрийн төхөөрөмж ашигладаг.
  • Cloud Computing — 4 төрөл: Нийтийн, Хувийн, Эрлийз, Тусгай.
  • Powerline Networking — өгөгдлийг цахилгааны утасаар дамжуулна.
  • WISP — Утасгүй интернэт үйлчилгээ үзүүлэгч: хөдөөгийн нутагт хандалтын цэгүүд.

Интранет ба Экстранет

  • Intranet — байгууллагын дотоод сүлжээ, зөвхөн ажилтнуудад.
  • Extranet — гадаад түншүүдэд (үйлчлүүлэгч, нийлүүлэгч) дотоод сүлжээний нэг хэсэгт хамгаалалттай хандалт олгодог.

Протокол ба Загварууд

OSI, TCP/IP, инкапсуляци, PDU, хаяглалт

Харилцааны элементүүд

Аливаа харилцаа гурван элементтэй: илгээгч (sender), хүлээн авагч (receiver), суваг (media).

Протоколууд тодорхойлно: илгээгч/хүлээн авагчийг таних, нийтлэг хэл, хурд ба цаг хугацаа, хүлээн авсан эсэхийн баталгаа.

Мессеж хүргэх арга

  • Unicast — нэгээс нэгд.
  • Multicast — нэгээс олонд (бүгдэд биш).
  • Broadcast — нэгээс бүгдэд. Зөвхөн IPv4 — IPv6 broadcast ашиглахгүй!
  • Anycast — IPv6-д шинэ төрөл: бүлгийн хамгийн ойр гишүүнд хүргэнэ.

Инкапсуляци ба PDU

Стекээр доош шилжих үед өгөгдөл шинэ нэр авна:

Програм → Өгөгдөл
Тээвэр → Сегмент (TCP/UDP толгой нэмэгдэнэ)
Сүлжээ → Пакет (IP толгой нэмэгдэнэ)
Өгөгдлийн холбоо → Фрейм (MAC толгой + FCS нэмэгдэнэ)
Физик → Битүүд (физик орчин дахь битүүд)

Де-инкапсуляци — урвуу процесс: бит → фрейм → пакет → сегмент → өгөгдөл.

Хаяглалт: L3 ба L2

  • IP хаяг (L3) — логик, глобал, хоп болгонд өөрчлөгдөхгүй.
  • MAC хаяг (L2) — физик, локал, хоп болгонд өөрчлөгдөнө (холбоос-холбоос хооронд).
⚡ Чухал баримт

IP эх ба очих хаяг нь хостоос хост хүрэх бүхэл замд ӨӨРЧЛӨГДӨХГҮЙ. MAC хаяг роутер болгонд өөрчлөгдөнө (хоп болгонд шинэ MAC src/dst ашигладаг).

Физик давхаргын үүрэг

Физик давхарга нь Data Link-ийн фреймийг хүлээн аваад орчинд дамжуулахаар дохионы цуврал болгон кодолно. Гурван функциональ хэсэг: Физик бүрэлдэхүүн (тоног төхөөрөмж), Кодлол, Дохиологоо.

Зурваасын өргөний нэр томьёо

  • Latency — хоцролт: A-с B хүрэх хугацаа.
  • Throughput — дамжуулах чадвар: хугацааны туршид бодитоор дамжуулсан битийн хэмжээ.
  • Goodput = Throughput − нэмэлт ачаалал (үйлчилгээний трафик). Хэрэгтэй хурд.

Хамгийн өргөн тархсан төрөл. Хямд, суурилуулахад амархан. Хязгаарлалт: зайнаас хамааран дохио сулрах (attenuation), EMI/RFI болон харилцан алдагдал (crosstalk) хөндлөнгийн нөлөө.

Коаксиаль кабель

Утасгүй төхөөрөмжид антен холбоход болон кабелийн интернэтэд хэрэглэнэ. 4 давхарга: зэс дамжуулагч → уян хатан хуванцар тусгаарлалт → зэсийн нэхмэл (экран) → гадна бүрхэвч.

Шилэн кабель

Өгөгдлийг урт зайд, өндөр хурдаар дамжуулдаг. EMI/RFI-д бүрэн тэсвэртэй. Нимгэн шилэн торноос хийгдсэн. Лазер эсвэл LED ашигладаг.

LLC — Логик холбооны удирдлага

Дээд давхаргуудтай харилцана. Ямар сүлжээний давхаргын протокол хэрэглэгдэж байгааг тодорхойлно (IPv4 эсвэл IPv6).

MAC — Орчинд хандах удирдлага

Өгөгдлийн инкапсуляци, орчинд хандах удирдлага, алдаа илрүүлэх (FCS).

Топологиуд

  • Point-to-point WAN — хоёр зангилаа, хамгийн энгийн. Мөргөлдөөн байхгүй.
  • Hub and Spoke WAN — төв сайт, туяа холболт.
  • Mesh WAN — бүгдийн бүгдтэй, өндөр хүртээмжтэй ч үнэтэй.
  • Star LAN — бүгд төв свитчээр дамжуулан (хамгийн түгээмэл).
  • Bus LAN — бүгд нэг кабель дээр (хуучирсан).
  • Ring LAN — төхөөрөмж болгон хөршүүдтэйгээ холбогдсон (хуучирсан Token Ring).

Дуплекс

  • Хагас дуплекс — нэг цагт зөвхөн нэг төхөөрөмж дамжуулна. WLAN болон хуучин хаб сүлжээнд хэрэглэнэ. Мөргөлдөөн боломжтой.
  • Бүрэн дуплекс — хоёр төхөөрөмж нэгэн зэрэг дамжуулж болно. Ethernet свитчүүд бүрэн дуплексээр ажилладаг. Мөргөлдөөн байхгүй.

Орчинд хандах удирдлагын арга

CSMA/CD — Мөргөлдөөн илрүүлэх

Хуучин Ethernet (хабтай) хэрэглэнэ. Хагас дуплекс. Мөргөлдөөн үед: төхөөрөмжүүд илрүүлж, санамсаргүй хугацаа хүлээгээд дахин дамжуулна.

CSMA/CA — Мөргөлдөөнөөс зайлсхийх

Wi-Fi (802.11)-д хэрэглэнэ. Хагас дуплекс. Дамжуулах хугацаанд орчныг захиална, бусад хэдий хүлээхийг мэднэ. Мөргөлдөөнийг урьдчилан сэргийлдэг.

VLAN ба Trunking

Логик сегментчлэл, 802.1Q, DTP

VLAN гэж юу вэ

VLAN — нэг свитч дотор сүлжээг логикоор хуваах. Өөр VLAN-д байгаа төхөөрөмжүүд роутер эсвэл L3 свитчгүйгээр харилцаж чадахгүй.

Давуу талууд: broadcast домэйн жижгэрнэ, аюулгүй байдал сайжирна, удирдлага уян хатан болно, зардал буурна.

802.1Q тэмдэглэлт

802.1Q тэг нь VLAN мэдээллийг транкоор дамжуулахын тулд Ethernet фреймд нэмэгддэг.

  • Тэгийн хэмжээ: 4 байт
  • TPID (Тэгийн протоколын ID): 0x8100 — 2 байт, энэ нь 802.1Q тэг гэдгийг заана
  • User Priority: 3 бит — QoS-д (CoS)
  • CFI (Каноник форматын таних тэмдэг): 1 бит — Token Ring фреймийн дэмжлэг
  • VID (VLAN ID): 12 бит → 4096 VLAN хүртэл дэмжнэ (2¹²)
⚠️ Native VLAN

Native VLAN-ийн трафик транкоор тэмдэглэгдэхгүйгээр дамжина. Транкын хоёр үзүүр ижил Native VLAN-тай байх ёстой. Анхдагч нь VLAN 1.

Транк тохиргоо

SW(config)# interface fa0/1
SW(config-if)# switchport mode trunk
SW(config-if)# switchport trunk native vlan 99
SW(config-if)# switchport trunk allowed vlan 10,20,30,99
SW(config-if)# end

SW# show interfaces fa0/1 trunk

EtherChannel

PAgP, LACP, сувгийн нэгтгэл

EtherChannel гэж юу вэ

EtherChannel нь хэд хэдэн физик Ethernet сувгийг нэг логик суваг болгон нэгтгэдэг. STP нэг порт гэж хардаг → блоклохгүй. Алдааг тэсвэрлэх чадвар ба ачааллын тэнцвэрлэлтийг хангана.

  • Нэг EtherChannel-д 8 порт хүртэл.
  • Catalyst 2960 6 EtherChannel хүртэл дэмждэг.
  • Хамгийн өндөр хурд: 800 Mbps (Fast) эсвэл 8 Gbps (Гигабит EtherChannel).
  • Нэг EtherChannel дотор өөр өөр төрлүүдийг (Fast + Gigabit) холих боломжгүй.

Шилжүүлэлтийн ойлголт

MAC хүснэгт, шилжүүлэлтийн аргууд, домэйнүүд

MAC хүснэгт (CAM хүснэгт)

Свитч эхийн MAC + порт бичин MAC хаягийн хүснэгт бүтээдэг. Хоёр алхамт процесс:

  • Сурах: Эхийн MAC-г харна → хүснэгтэд байхгүй бол нэмнэ. Таймаут 5 минут-д тавигдана.
  • Дамжуулах: Очих MAC-г харна → хүснэгтэд байвал тодорхой порт руу илгээнэ. Байхгүй бол flooding (орох портоос бусад бүх порт руу).
📌 Flooding

Очих MAC тодорхойгүй эсвэл broadcast бол фрейм нь орох (ingress) портоос бусад бүх порт руу илгээгддэг. Ingress = орох порт, Egress = гарах порт.

Шилжүүлэлтийн аргууд

Store-and-Forward (Cisco-ийн илүүд үзсэн)
  • Бүх фреймийг бүхэлд нь хүлээн авна
  • FCS (CRC) шалгана — гэмтсэн фреймийг устгана
  • Буфержилт → өөр хурдтай портуудыг дэмжинэ
  • Шалгалтын улмаас удаан
Cut-Through
  • Очих MAC-г уншсаны дараа шууд дамжуулна
  • FCS шалгахгүй → алдаа тархуулж болно
  • Хурдан: хоцролт <10 микросекунд
  • Өөр хурдтай портуудыг дэмждэггүй
Fragment-Free

Cut-Through-ийн хувилбар. Runt фреймүүдийг (64 байтаас бага) шүүхийн тулд эхний 64 байтыг уншина (Ethernet фреймийн хамгийн бага хэмжээ). Хурд ба найдвартай байдлын тэнцвэр.

Домэйнүүд

  • Мөргөлдөөний домэйн — мөргөлдөөн үүсгэж болох төхөөрөмжүүдийн бүлэг. Свитч хоп болгонд тусдаа мөргөлдөөний домэйн үүсгэдэг (бүрэн дуплекст мөргөлдөөн байхгүй). Хаб — нэг том домэйн.
  • Broadcast домэйн — broadcast хүлээн авдаг төхөөрөмжүүд. Свитч broadcast домэйнийг өргөтгөнө. Зөвхөн роутер (L3) broadcast домэйнийг хуваана.
STP

STP — Spanning Tree Protocol

L2 сүлжээн дэх гогцоог сэргийлэх

STP яагаад хэрэгтэй вэ

STP-гүйгээр илүүдэл замтай сүлжээнд L2 гогцоо үүснэ. Үр дагавар: MAC хүснэгтийн тогтворгүй байдал, суваг дүүргэлт, CPU 100% — сүлжээ ажиллахаа болино.

Broadcast Storm — хэдхэн секундын дотор сүлжээг доголдуулах хэтэрхий олон broadcast пакет.

ℹ️ STP-ийн түүх

STP-г Radia Perlman 1985 онд Digital Equipment Corporation-д ажиллаж байхдаа бүтээсэн. Алгоритмыг "An Algorithm for Distributed Computation of a Spanning Tree in an Extended LAN" нийтлэлд нийтэлсэн.

STP хэрхэн ажилладаг вэ

  • Root Bridge сонголт — нэг свитч "мод-ийн үндэс" болно. Бусад бүгд түүн рүү хүрэх замыг бүтээнэ.
  • Илүүдэл замыг блоклох — Blocking горимын портууд хэрэглэгчийн трафик дамжуулахгүй.
  • Гэмтэл үед дахин тооцоолох — зам унахад STP нөөц замыг нээнэ.

MAC хаяг

  • 48 бит (6 байт), XX:XX:XX:XX:XX:XX hex хэлбэрээр бичигддэг.
  • Эхний 3 байт — OUI (Байгууллагын өвөрмөц таних тэмдэг), IEEE-ийн үйлдвэрлэгчид олгодог.
  • Сүүлийн 3 байт — үйлдвэрлэгчийн тогтоосон төхөөрөмжийн өвөрмөц таних тэмдэг.
  • FF:FF:FF:FF:FF:FF — broadcast MAC хаяг.
  • Эхний байтын хамгийн бага битийн хоёр дахь бит = 1 → multicast/broadcast.
ARP

ARP ба ND — Хаяг зохицуулалт

IP ↔ MAC зөрүүлэлт

ARP — Хаяг зохицуулалтын протокол (IPv4)

ARP нь нэг сүлжээний хүрээнд мэдэгдэж байгаа IP хаягаар MAC хаяг олоход ашиглагдана.

  • ARP хүсэлт — broadcast (FF:FF:FF:FF:FF:FF). "X.X.X.X IP хаяг хэнд байна вэ?"
  • ARP хариу — хүсэлт тавьсан руу unicast. "Энэ би, миний MAC — XX:XX:XX..."

Үр дүнг ARP хүснэгт-т (ARP cache) кэш болгон хадгалдаг. Шалгах: arp -a (Windows) эсвэл show ip arp (Cisco).

⚠️ ARP Spoofing

Халдагч хуурамч ARP хариу илгээж болно → MAC хаяг солигдоно → трафик таслагдана (Хооронд орох халдлага).

ND — Хөршийн илрүүлэлт (IPv6)

IPv6 ARP ашиглахгүй. Оронд нь Neighbor Discovery Protocol (NDP), ICMPv6 ашигладаг:

  • NS (Хөршийн хүсэлт) — MAC хаяг хүсэлт (ARP хүсэлттэй адил).
  • NA (Хөршийн зар) — MAC хаягтай хариу (ARP хариутай адил).
  • RS (Роутерийн хүсэлт) — роутерийн мэдээлэл хүсэх.
  • RA (Роутерийн зар) — роутер сүлжээний параметр тархаана.

OSPF

Нэг бүс OSPFv2

Холбоосын-байдал протокол, DR/BDR, зардал

OSPF шинж чанарууд

  • Төрөл: Холбоосын-байдал (RIP шиг зайн вектор биш).
  • Административ зай: 110.
  • Метрик: Зардал (Cost). Бага = сайн.
  • Алгоритм: Dijkstra SPF (Хамгийн богино зам эхлэлтэй).
  • VLSM ба CIDR дэмждэг.
  • Процессийн ID: 1–65535, локал (өөр роутеруудад тохирох шаардлагагүй).

Зардлын (Cost) томъёо

Зардал = Лавлагааны зурваасын өргөн / Интерфейсийн зурваасын өргөн

Анхдагч лавлагааны зурваасын өргөн = 10⁸ = 100,000,000 bps = 100 Mbps

ИнтерфейсЗурваасын өргөнЗардал (ref=100M)Зардал (ref=10G)
FastEthernet100 Mbps1100
GigabitEthernet1 Gbps1 ⚠️10
10GigabitEthernet10 Gbps1 ⚠️1

⚠️ ref=100M үед Gigabit болон Fast Ethernet ижил cost=1-тэй. Лавлагааны зурваасыг өөрчлөх хэрэгтэй: auto-cost reference-bandwidth 10000

Роутерийн ID

OSPF Роутерийн ID-г дараах тэргүүлэх дарааллаар сонгоно:

  1. Тодорхой тохируулсан: router-id X.X.X.X
  2. Loopback интерфейс дэх хамгийн өндөр IP
  3. Идэвхтэй физик интерфейс дэх хамгийн өндөр IP

OSPF үндсэн тохиргоо

R1(config)# router ospf 10
R1(config-router)# router-id 1.1.1.1
R1(config-router)# network 10.1.1.0 0.0.0.3 area 0
R1(config-router)# network 10.10.1.0 0.0.0.255 area 0
R1(config-router)# passive-interface loopback 0   ! OSPF Hello илгээхгүй

! Эсвэл интерфейст шууд:
R1(config)# interface g0/0/0
R1(config-if)# ip ospf 10 area 0

! Лавлагааны зурваасыг өөрчлөх (бүх роутерт ижилхэн байх ёстой!):
R1(config-router)# auto-cost reference-bandwidth 10000

! Зардлыг гараар өөрчлөх:
R1(config-if)# ip ospf cost 15

OSPF таймер

  • Hello интервал: 10 секунд (p2p болон multiaccess дээр анхдагч)
  • Dead интервал: 40 секунд = 4 × Hello. Энэ хугацааны дараа хосыг "унасан" гэж үзнэ.
  • Хоёул хоёр үзүүрт тохирч байх ёстой — тохирохгүй бол adjacency үүсэхгүй!
! Таймер өөрчлөх:
R1(config-if)# ip ospf hello-interval 5
R1(config-if)# ip ospf dead-interval 20

Multiaccess сүлжээн дэх DR ба BDR

Multiaccess (Ethernet) сүлжээнд OSPF нь LSA трафикийг багасгахын тулд DR (Томилогдсон роутер) ба BDR (Нөөц DR) сонгодог.

DR/BDR сонголт:

  1. Интерфейс дэх хамгийн өндөр OSPF Priority (анхдагч = 1). Priority=0 → DR/BDR болж чадахгүй.
  2. Priority ижил байвал → хамгийн өндөр Роутерийн ID.
⚠️ DR сонголт — урьдчилан давах биш!

DR/BDR сонгогдсоны дараа өндөр priority/ID-тэй шинэ роутер нэмэгдэх нь одоогийн DR-ийг солихгүй. Сонголт зөвхөн анх ажиллах үед эсвэл DR унах үед явагддаг.

! OSPF Priority өөрчлөх:
R1(config)# interface g0/0/0
R1(config-if)# ip ospf priority 255   ! (0-255, анхдагч=1)

! OSPF дахин эхлүүлэх (шинэ DR сонголтод):
R1# clear ip ospf process

Статик NAT — 1:1

R2(config)# interface serial 0/1/0
R2(config-if)# ip nat inside
R2(config)# interface serial 0/1/1
R2(config-if)# ip nat outside
Динамик NAT — хаягийн цуур

Нийтийн хаягийн цуур шаардлагаар хуваарилагдана. Цуур дүүрвэл хүлээнэ.

R2(config)# ip nat pool NAT-POOL1 209.165.200.226 209.165.200.240 netmask 255.255.255.224
R2(config)# access-list 1 permit 192.168.0.0 0.0.255.255
R2(config)# ip nat inside source list 1 pool NAT-POOL1
PAT (NAT Overload) — олон:нэг

Олон хувийн хаяг нэг нийтийн хаяг дээр. TCP/UDP портын дугаараар ялгагдана. Хамгийн түгээмэл төрөл.

! PAT нэг IP-тэй (интерфейс):
R2(config)# ip nat inside source list 1 interface serial 0/1/1 overload

! PAT цуурын хамт:
R2(config)# ip nat pool NAT-POOL2 209.165.200.226 209.165.200.240 netmask 255.255.255.224
R2(config)# ip nat inside source list 1 pool NAT-POOL2 overload

PAT дэх портууд

PAT анхны эхийн портыг хадгалдаг. Порт аль хэдийн ашиглагдаж байвал PAT дараах мужаас дараагийн чөлөөт портыг авна:

  • 0–511
  • 512–1023
  • 1024–65535

TCP 3 алхамт Handshake (Холболт тогтоох)

Клиент → SYN → Сервер    (холбогдохыг хүсэж байна)
Клиент ← SYN+ACK ← Сервер    (баталгаажуулж байна, хүлээж байна)
Клиент → ACK → Сервер    (хүлээн авав, холболт тогтов)

TCP 4 алхамт дуусгавар (Сессий дуусгах)

Клиент → FIN → Сервер    (илгээх зүйл алга)
Клиент ← ACK ← Сервер    (FIN хүлээн авав)
Клиент ← FIN ← Сервер    (манайд ч илгээх зүйл алга)
Клиент → ACK → Сервер    (хүлээн авав, холболт хаагдав)

MSS ба Цонхны хэмжээ

  • MSS (Хамгийн их сегментийн хэмжээ) — TCP сегмент дэх өгөгдлийн хамгийн их хэмжээ.
  • Стандарт MSS = 1460 байт (1500 MTU − 20 TCP толгой − 20 IP толгой = 1460).
  • Цонхны хэмжээ — ACK-гүйгээр илгээх байтын тоо. Урсгал удирдлагын механизм.
  • SACK (Сонгомол баталгаажуулалт) — бүгдийг биш тодорхой сегментийг баталгаажуулах боломж.
  • Гулсагч цонх (Sliding Window) — ACK хүлээн авах тусам цонх шилжинэ.

Програмын давхарга

HTTP, DNS, DHCP, FTP, Имэйл протоколууд

TCP/IP програмын давхаргын OSI давхаргууд

  • Програм (7) — харилцан үйлчлэлийн протоколууд (HTTP, DNS, FTP).
  • Танилцуулга (6) — форматлах, шахах, шифрлэх/тайлах.
  • Сессий (5) — яриа, сессий удирдах.

Клиент-сервер ба P2P загварууд

  • Клиент-Сервер — клиент хүсэлт тавьж, сервер нөөц хангана.
  • Үе тэнгийн-Үе тэнгийн (P2P) — хоёр төхөөрөмж нэгэн зэрэг клиент болон сервер байж болно. Тусгай сервер байхгүй.

HTTP / HTTPS

  • HTTP — порт 80, TCP.
  • HTTPS — порт 443, TCP. Шифрлэгдсэн.
  • Аргууд: GET (хуудас авах), POST (серверт өгөгдөл илгээх), PUT (өгөгдөл шинэчлэх).

DHCP — DORA процесс

1. DISCOVER — клиент broadcast: "DHCP сервер байна уу?"
2. OFFER — сервер unicast/broadcast: "ийм IP чинийх"
3. REQUEST — клиент broadcast: "X серверийн санал зөвшөөрч байна"
4. ACK — сервер: "баталгаажлаа, IP X хугацаанд чинийх"

Санал хүчингүй бол → NACK → процесс эхнээс эхэлнэ.

IPv6 аналог: SOLICIT → ADVERTISE → REQUEST → REPLY

  • DHCP Клиент порт: 68 (UDP)
  • DHCP Сервер порт: 67 (UDP)

FTP — Файл дамжуулах протокол

  • Порт 21 — Удирдлагын холболт (командууд). Сессийн турш нээлттэй байна.
  • Порт 20 — Өгөгдлийн холболт (файл дамжуулалт). Дамжуулалт болгонд нээгддэг.
  • FTP клиент файл татаж авах (pull) болон илгээх (push) боломжтой.

SMB — Серверийн мессежийн блок

Файл ба принтер хуваалцах протокол. Клиент серверт холбогдон файлтай нь локал мэт ажилладаг. SMB мессежийн гурван функц:

  • Сессий эхлүүлэх, баталгаажуулалт, дуусгавар.
  • Файл, принтерт хандалт удирдах.
  • Програм хангамжид нөгөө төхөөрөмжтэй мессеж солилцох боломж олгох.
ACL

ACL — Хандалт хянах жагсаалт

Трафик шүүх, wildcard маск, ACL төрлүүд

ACL гэж юу вэ

ACL — толгойн мэдээллээр пакет шүүхийн тулд IOS командуудын цуврал. Анхдагчаар роутерт ACL байхгүй. ACL нь ACE (Хандалт хянах бичлэг) агуулдаг — дарааллагдсан permit/deny дүрэм.

⚠️ Далд татгалзал

Аль ч ACL-ийн төгсгөлд далд deny all байдаг — нуугдсан deny any мөр. Тодорхой дүрэмд тохирохгүй бүх трафик — блоклогдоно. ACL хамгийн багадаа нэг permit дүрэм агуулах ёстой!

ACL-ийн төрлүүд

Стандарт ACL — Дугаар 1-99 ба 1300-1999
  • Зөвхөн Эхийн IP-д шүүнэ (3-р давхарга)
  • Хамгийн ойрхон очих газар-д байрлуулна
Өргөтгөсөн ACL — Дугаар 100-199 ба 2000-2699
  • Эхийн IP, Очих IP, протокол, портод шүүнэ (3-р + 4-р давхарга)
  • Хамгийн ойрхон эх-д байрлуулна

ACL дэх Wildcard маск

Wildcard маск — дэд сүлжээний маскийн урвуу. Бит 0 = шалгах (match), бит 1 = үл тоох.

Wildcard тооцоолох: 255.255.255.255 − дэд сүлжээний маск = wildcard

  • Хост: 192.168.1.1 0.0.0.0 → зөвхөн энэ IP
  • /24 сүлжээ: 192.168.1.0 0.0.0.255 → бүх 192.168.1.x
  • /28 сүлжээ: 192.168.1.32 0.0.0.15 → дэд сүлжээний 14 хост

Түлхүүр үгс:

  • host = 0.0.0.0 wildcard (яг энэ хост)
  • any = 255.255.255.255 wildcard (ямар ч IP)

ACL хэрэглэх

  • Inbound ACL — чиглүүлэхийн өмнө шүүнэ. Илүү үр ашигтай (устгагдах пакетад routing lookup хийхгүй).
  • Outbound ACL — чиглүүлсний дараа шүүнэ.
  • Нэг интерфейст: 1 inbound IPv4 ACL + 1 outbound IPv4 ACL + 1 inbound IPv6 ACL + 1 outbound IPv6 ACL = хамгийн ихдээ 4 ACL байж болно.

ACL тохиргооны жишээ

! Стандарт ACL (дугаарлагдсан):
R1(config)# access-list 10 permit 192.168.1.0 0.0.0.255
R1(config)# access-list 10 deny any
R1(config)# interface g0/0
R1(config-if)# ip access-group 10 out

! Өргөтгөсөн ACL:
R1(config)# access-list 110 permit tcp 192.168.1.0 0.0.0.255 any eq 80
R1(config)# access-list 110 deny ip any any

! Нэрлэгдсэн ACL (илүү тохиромжтой):
R1(config)# ip access-list standard BLOCK-SALES
R1(config-std-nacl)# deny 192.168.2.0 0.0.0.255
R1(config-std-nacl)# permit any

! Интерфейст хэрэглэх:
R1(config)# interface g0/1
R1(config-if)# ip access-group BLOCK-SALES in

! Шалгах:
R1# show access-lists
R1# show ip interface g0/0
✅ ACL-ийн шилдэг дадлага
  • Байгууллагын аюулгүй байдлын бодлогод үндэслэн ACL боловсрул.
  • Командууд бичихийн өмнө ACL юу хийхийг бич.
  • ACL үүсгэх, засахад текст засварлагч ашигла.
  • remark командаар ACL-ийг баримтжуул.
  • Үйлдвэрлэлийн сүлжээнд хэрэглэхийн өмнө туршилтын сүлжээнд тест хий.
